# 펩타이드/단백질 설계 연습 앱 — 계획 문서

## Context

논문·웹 DB에 공개된 펩타이드/단백질을 찾아 서열을 가져오고, 그 서열을 변형해 새 펩타이드/단백질을 만든 뒤 3D 구조를 확인하는 **학습용 앱**을 만든다. 목적은 "검색 → 서열 확보 → 변이 설계 → 물성 분석 → 구조 예측/비교"의 전체 흐름을 직접 체험하는 것이다. 프로덕션 수준의 신약 설계 도구가 아니라 연습용이므로, 단순함과 이해하기 쉬운 코드를 우선한다.

**확정된 선택**
- 형태: Streamlit 웹앱 (Python 3.11 사용, Node.js 불필요)
- 설계 범위: 수동 변이 + 규칙 기반 (ML 설계 모델 제외)
- 구조 확인: AlphaFold DB(기존 단백질 조회) + ESMFold API(변이체 예측) 병용

## 핵심 기능 (4개 탭)

1. **검색 (Search)** — 서열 출처를 단계별로 탐색하는 **폴백 체인**
   - 1단계 단백질/펩타이드 DB: UniProt(ID·키워드·유전자명) → PDB(실험 구조 속 펩타이드) → 펩타이드 전용 DB(APD3, DRAMP, CAMP 등; 공개 다운로드/API가 되는 것만 연동)
   - 2단계 **논문 기반** (DB에 없을 때): Europe PMC/PubMed에서 키워드 검색 → 초록·오픈액세스 전문 수집 → 서열 후보 자동 추출
   - 3단계 **특허 기반**: 특허 서열목록(SEQ ID NO) 검색 — NCBI/EBI의 특허 서열 데이터(GenBank PAT, EBI 특허 단백질 서열), Google Patents/Lens/WIPO PATENTSCOPE 링크 및 특허 본문(청구항·서열목록 섹션) 파싱
   - **서열 후보 추출기** (`seqextract.py`): 본문에서 (a) 1문자 표기 서열(예: `GIGAVLKVLTTGLPALISWIKRKRQQ`, 길이 5~100, 표준 20 아미노산만으로 구성), (b) 3문자 표기(`Gly-Ile-Gly-...`), (c) `SEQ ID NO: n` 근처 서열을 정규식으로 찾아 후보 표로 제시. 사용자가 **눈으로 확인·수정 후 채택**(자동 추출은 오탐 가능하므로 반드시 사용자 검토 단계를 둔다)
   - **출처 기록(provenance)**: 채택한 서열마다 출처 유형(UniProt/논문/특허), 식별자(PMID·DOI·특허번호·SEQ ID NO), URL, 확인 일자를 함께 저장하고 이후 모든 탭에 표시
   - **발굴(스크리닝) 방법 — 선택 목록에서 고르기**: 사용자가 논문을 읽고 목록에서 직접 선택한다(복수 선택 가능, 기본값 "미보고"). 자동 추출은 하지 않는다.
     - 목록: 파지 디스플레이(biopanning) / 효모·박테리아 표면 디스플레이 / mRNA·리보솜 디스플레이 / DEL·OBOC 비드 라이브러리 / 합성 펩타이드 라이브러리(어레이, 알라닌 스캐닝 등) / 기능 기반 HTS(MIC, 세포·효소 어세이) / 천연물 분획 / 인실리코 스크리닝 / 기타·불명
     - 자유 텍스트 메모 칸(라운드 수, 선택 압력 등 선택 사항)
     - UniProt `proteinExistence`·`Direct protein sequencing` 키워드와 PDB 실험 방법은 "참고 정보"로만 표시
   - **결합 대상(표적) — 논문에서 가져오되 사용자가 확인**: 특히 표면 결합 펩타이드는 "무엇에 붙는가"를 명확히 서술
     - 논문 초록(또는 붙여넣은 본문)에서 **소재 키워드 사전**(titanium, gold, silica, polystyrene, hydroxyapatite, graphene, stainless steel 등)을 매칭해 결합 대상 **후보**를 제안하고, 근거 문장 1개(짧은 발췌)와 함께 보여준다. 사용자가 후보를 고르거나 직접 입력·수정해서 확정한다("제안" vs "확정" 구분 표시)
     - 필드(`binding_target`): 구체 명칭 + 분류(무기 소재 / 금속 / 고분자 / 탄소 소재 / 생체 소재 / 세포·조직 / 단백질·핵산 / 기타) + 형태·조건 메모(자유 텍스트: 박막/나노입자, pH, 완충액 등). 명시되지 않으면 "미보고"(추측으로 채우지 않음)
     - **결합 친화도(Kd 등)와 측정 방법**: v1에서는 제외했으나 v1.1에서 **논문에 보고된 값의 기록**(`src/affinity.py`)과 **학습용 경험적 결합 성향 점수**(`src/analysis/binding_score.py`)로 추가했다. 자동 확정은 하지 않고 본문 값 후보는 "제안"으로만 넣는다
     - 서열 헤더에 요약 문장을 항상 표시: "이 펩타이드는 **[대상]**에 결합, 발굴 방법: **[방법]**" (값이 없으면 "미보고")
     - 변이체는 "설계된 서열(비실험)"로 표시하고, 부모의 결합 대상·발굴 방법은 참조 정보로만 연결(변이가 결합을 유지한다고 암시하지 않음)
   - **비표준 요소 경고**: D-아미노산, N/C-말단 변형(아세틸화·아마이드화), 고리화(이황화 결합·head-to-tail), 비천연 아미노산(`Aib`, `Orn`, `Nle` 등)은 표준 서열로 단순화하면서 원문 표기를 메모로 남기고 "구조 예측 시 무시됨" 경고 표시
   - 선택 시 FASTA 서열, 기능 요약, 관련 PDB/AlphaFold 링크, 참고문헌(PMID 링크) 표시
   - 직접 입력도 지원: 논문에서 읽은 서열을 붙여넣고 출처만 수기로 기록
   - 학습용 **예시 프리셋**: 인슐린 B/A쇄, GLP-1(7-36), 멜리틴, 마가이닌, LL-37, 인간 유비퀴틴, GFP 등 (+ 논문/특허 기반 입력 연습용 예시 1~2개)
2. **설계 (Design)**
   - 서열 입력(검색 결과 불러오기 / 직접 붙여넣기 / FASTA 업로드), 검증(표준 20 아미노산만 허용)
   - 변형 도구: 점돌연변이(예: `K12A`), 알라닌 스캐닝, 구간 삭제/삽입, 잘라내기(truncation), 두 서열 융합(링커 `GGGGS` 옵션), 역서열/무작위 셔플(음성 대조), 보존 치환 제안
   - 변이체를 세션에 여러 개 저장하고 이름 붙이기
3. **분석·스크리닝 (Analyze / Screen)** — 단순 분석보다 **가상 스크리닝 워크플로**를 중심에 둔다
   - **가상 라이브러리 생성**: 부모 서열에서 알라닌 스캐닝, 위치별 전체 치환(site-saturation), 무작위 변이 N개, 절단체 세트를 한 번에 생성 (실제 라이브러리 스크리닝을 모사)
   - **필터 → 점수 → 순위화(screening funnel)**: 단계별 필터(길이, 순전하 범위, 소수성/GRAVY 범위, 불안정성 지수, 금지 모티프·Cys 개수 등)를 슬라이더로 설정 → 통과 후보 수 깔때기 차트로 표시 → 간단한 점수식(예: 양친매성/전하 기반 항균 점수 학습용 휴리스틱, 부모와의 동일성) 정렬 → 상위 후보를 변이체로 저장
   - **(선택 단계, 기본 꺼짐)** 구조 기반 재순위화: 사용자가 켠 경우에만 상위 N개(기본 3개)를 구조 탭에서 ESMFold로 예측해 부모 대비 pLDDT를 비교 (비용 큰 단계를 마지막에 두는 스크리닝 순서 학습). 구조 없이 기능하는 표면 결합 펩타이드 등에서는 건너뛰어도 되며, 켜더라도 짧은 펩타이드(< ~30 aa)는 pLDDT가 낮을 수 있다는 경고를 함께 표시한다. 이 단계를 건너뛰어도 순위화 결과 저장과 이후 흐름은 동일하게 동작
   - 개별 서열 분석 도구:
   - 물성: 길이, 분자량, pI, 순전하(pH 7.4), GRAVY(소수성), 불안정성 지수, 방향족성 (Biopython `ProteinAnalysis`)
   - 서열 정렬: 원본 vs 변이체 (Biopython `PairwiseAligner`), 동일성(%) 및 차이 위치 하이라이트
   - 시각화: 잔기별 소수성 플롯, Helical wheel(양친매성 펩타이드 학습용), 아미노산 조성 막대그래프
4. **구조 (Structure)**
   - 원본: UniProt ID → AlphaFold DB에서 PDB/mmCIF + pLDDT 조회; 실험 구조는 RCSB PDB 로드
   - 변이체: ESMFold API로 예측 → PDB 문자열 수신
   - 3D 뷰어(py3Dmol/stmol): pLDDT 색상, cartoon/stick 전환, 변이 잔기 강조
   - 두 구조 나란히 보기 (기본 기능)
   - **(선택 기능, 기본 꺼짐)** 원본 vs 변이체 구조 중첩 및 RMSD: 사용자가 켠 경우에만 계산한다 (Biopython `Superimposer`, Cα 기준). 원자 수가 같아야 하므로 **길이가 같은 변이체(점돌연변이 등)에만** 제공하고, 삽입·삭제로 길이가 다르면 비활성화하며 이유를 안내한다
   - 결과 PDB 다운로드

## 외부 데이터 소스 (모두 무료·키 불필요)

| 용도 | 엔드포인트 |
|---|---|
| 서열/메타데이터 검색 | UniProt REST: `rest.uniprot.org/uniprotkb/search`, `/uniprotkb/{acc}.fasta` / `.json` |
| 실험 구조 | RCSB: `data.rcsb.org/rest/v1/core/entry/{id}`, `files.rcsb.org/download/{id}.pdb` |
| 예측 구조(기존) | AlphaFold DB: `alphafold.ebi.ac.uk/api/prediction/{uniprot}` → `pdbUrl` |
| 예측 구조(변이체) | ESMFold: `POST api.esmatlas.com/foldSequence/v1/pdb/` (본문=서열) |
| 논문 검색/초록 | Europe PMC REST: `www.ebi.ac.uk/europepmc/webservices/rest/search?query=...` (메타데이터·초록), 오픈액세스 전문은 `/{PMCID}/fullTextXML` |
| 논문 메타(보조) | NCBI E-utilities `esearch`/`esummary` (PMID → 제목/저널) |
| 특허 서열 | NCBI Protein/Nucleotide 특허 서열(PAT), EBI 특허 서열 데이터 |
| 특허 본문 | Google Patents / Lens / WIPO PATENTSCOPE / EPO OPS — 약관·접근 제한이 있어 **공개 API가 되는 범위만 연동**하고, 안 되는 곳은 검색 링크 + 본문 붙여넣기(수동)로 대체 |
| 펩타이드 DB(선택) | APD3, DRAMP 등 — 공개 다운로드 파일을 로컬 캐시로 인덱싱할 수 있을 때만 |

주의 사항:
- 논문·특허 본문은 저작권/약관이 있으므로 앱은 **서열과 출처 식별자만** 저장하고 본문 전체를 재배포하지 않는다. 유료 전문(비OA)은 가져오지 않고 링크만 제공한다.
- 특허 사이트는 스크래핑이 막혀 있을 수 있어 구현 시점에 접근 가능성을 먼저 확인하고, 불가하면 수동 붙여넣기 경로를 기본으로 둔다.
- (선택 기능) 추출 정확도를 높이기 위해 Claude API로 본문에서 서열·변형 정보를 구조화 추출하는 옵션을 둘 수 있음 — API 키가 필요하므로 기본은 정규식 방식, LLM 방식은 후순위.
- 짧은 펩타이드(< ~30 aa)는 ESMFold/AlphaFold가 구조를 낮은 신뢰도(pLDDT↓)나 무질서로 예측하는 경우가 많다. 앱에서 pLDDT 낮음 경고를 띄우고 "예측 한계"를 학습 포인트로 안내한다.
-  ESMFold 공개 API는 긴 서열(대략 400 aa 초과)에서 실패하거나 느릴 수 있어 입력 길이를 제한하고 안내 메시지를 표시한다. 외부 API 장애에 대비해 타임아웃·재시도·사용자 친화적 오류 메시지를 둔다. 요청 결과는 디스크 캐시(`data/cache/`)에 저장해 재호출을 줄인다. API 스키마는 구현 시점에 실제 응답으로 한 번 확인한다.

```
AI 바이브코딩/
├─ app.py                  # Streamlit 진입점, 탭 구성
├─ requirements.txt        # streamlit, biopython, requests, pandas, matplotlib, py3Dmol, stmol
├─ README.md               # 실행법, 학습 시나리오

│  ├─ sources/binding.py   # 소재 키워드 사전 기반 결합 대상 후보 제안 (친화도 파싱은 v1 제외)
│  ├─ provenance.py        # 서열 + 출처 + 발굴 방법 + 결합 대상 메타데이터 데이터 클래스 (SeqRecord)
│  ├─ design/              # mutate.py (변이 파서·적용), fuse.py, controls.py
│  ├─ analysis/            # properties.py, align.py, plots.py (hydropathy, helical wheel)
│  ├─ structure/           # esmfold.py, compare.py (RMSD/중첩), viewer.py
│  └─ presets.py           # 예시 펩타이드/단백질 목록
├─ tests/                  # mutate, properties, 파서 단위 테스트 (네트워크 호출은 mock)
└─ data/cache/             # API 응답 캐시 (gitignore)
```

설계 원칙: UI(`app.py`)와 로직(`src/`)을 분리해 로직은 Streamlit 없이도 테스트 가능하게 한다. 상태는 `st.session_state`에 변이체 딕셔너리(`{이름: SeqRecord}`)로 보관하며, `SeqRecord`는 서열·이름·출처(provenance)·발굴 방법(screening_method 선택 목록 + 메모)·결합 대상(binding_target: 명칭·분류·메모, 제안/확정/미보고 상태)·비표준 잔기 메모·부모 서열 참조를 가진다(변이체는 원본의 출처를 상속).

## 구현 단계

1. **골격**: 가상환경, `requirements.txt`, Streamlit 빈 탭 4개, 프리셋 로드
2. **검색 (DB)**: UniProt 클라이언트(검색·FASTA·참고문헌) + 결과 UI + `SeqRecord`/출처 기록
2b. **검색 (논문·특허)**: Europe PMC 검색·OA 전문 수집 → `seqextract.py` 후보 추출 → 사용자 검토/채택 UI → 특허 서열(접근 가능한 소스) 및 수동 붙여넣기 경로
3. **설계/분석**: 변이 파서(`K12A`, 범위 삭제 등) + 물성 계산 + 정렬 + 플롯, 단위 테스트
4. **구조**: AlphaFold DB 조회 → py3Dmol 뷰어 → ESMFold 연동 → (선택) RMSD 비교
5. **마감**: 캐시·오류 처리, README(학습 시나리오 3개), 샘플 워크스루 점검

## 검증 방법

- **단위 테스트**: `pytest` — 변이 적용(위치 범위 초과/잔기 불일치 오류 포함), 물성 값(알려진 서열의 MW·pI 기준값과 비교), 정렬 동일성
- **엔드투엔드(수동)**: `streamlit run app.py`로 실행 후 아래 시나리오 확인
  1. "melittin" 검색 → 서열(26 aa) 확인 → 물성 표시
  2. 알라닌 스캐닝으로 변이체 생성 → 원본과 정렬·소수성 비교
  3. 원본(AlphaFold DB 또는 ESMFold)과 변이체(ESMFold) 구조를 3D로 나란히 보고, (선택) RMSD를 켜서 확인 — 길이가 다른 변이체에서는 RMSD가 비활성화되는지도 확인
  3b. 가상 스크리닝: 알라닌 스캐닝+치환 라이브러리 생성 → 필터 깔때기 → 순위화 → (선택) 구조 기반 재순위화를 켜고 상위 3개만 ESMFold 예측, 끈 상태에서도 순위화·저장까지 정상 동작하는지 확인
  4. 400 aa 초과 서열 입력 시 ESMFold 제한 안내 메시지 확인
  5. **UniProt에 없는 펩타이드** (예: 논문에만 보고된 합성 항균 펩타이드) 검색 → UniProt 결과 없음 → Europe PMC 논문 검색 → 후보 서열 추출·채택 → 출처(PMID) 표시 확인 → 이후 설계/구조 탭까지 동일하게 동작
  6. 특허 경로: 특허번호 또는 키워드로 검색 → SEQ ID NO 서열 후보 추출(또는 본문 붙여넣기) → 채택 및 출처(특허번호·SEQ ID NO) 기록
  6b. 발굴 방법 표시: 선택 목록에서 "파지 디스플레이"를 고르면 서열 헤더에 표시되고, 안 고르면 "미보고"로 표시되는지 확인. UniProt 항목은 PE·키워드가 참고 정보로만 표시되는지, 변이체는 "설계된 서열(비실험)"로 표기되는지 확인
  6c. 표면 결합 펩타이드 예시(예: 티타늄/실리카/금 결합 파지 디스플레이 펩타이드 논문): 초록에서 소재 키워드(예: titanium)가 결합 대상 후보로 제안되고, 사용자가 선택·수정해 확정하면 요약 문장에 표시되는지, 소재 언급이 없는 논문에서는 "미보고"로 표시되는지, 변이체는 "설계된 서열(비실험)"로 표시되는지 확인
  7. 비표준 잔기(`Aib`, D-아미노산, 아마이드화 등)가 포함된 예시 입력 시 경고 및 원문 표기 메모 보존 확인
- `binding.py` 단위 테스트: 소재 키워드 매칭(대소문자·동의어, 예: Ti/titanium), 소재 언급이 없을 때 빈 후보 반환("미보고"), 부정·비교 문맥의 오탐은 사용자 확인 단계에서 걸러짐을 확인
- `seqextract.py` 단위 테스트: 1문자/3문자 표기, `SEQ ID NO` 패턴, 오탐 사례(일반 영단어 대문자열, 약어) 제외, 비표준 잔기 탐지
- 브라우저 확인은 내장 브라우저로 화면·콘솔 오류를 점검한다.
