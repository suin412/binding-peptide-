## 공통 규칙

- **UI와 로직 분리**: `app.py`는 화면만, 계산·API 호출은 `src/`에 둔다. 로직은 Streamlit 없이 `pytest`로 테스트한다.
- **네트워크 테스트는 mock**: 단위 테스트는 외부 API를 호출하지 않는다. 실제 API 응답은 `tests/fixtures/`에 저장한 샘플을 쓴다.
- **정직한 표시**: 모르는 값은 "미보고"로 표시하고 추정해서 채우지 않는다. 자동 제안값은 확정 전까지 구분해서 보여준다.
- **우선순위**: P0 → P1 → P2 순으로 구현하고, P2는 시간이 남을 때만 한다.
- **구현 시작 전 확인**: 외부 API는 마일스톤 첫 작업에서 실제 응답을 한 번 확인한 뒤 클라이언트를 작성한다 (스키마 변경 대비).
- **의존성**: 새 라이브러리는 `requirements.txt`에 추가하고, 추가 이유를 해당 마일스톤 문서에 한 줄 남긴다.

## 구현 중 계획에서 달라진 점

| 항목 | 계획 | 실제 |
|---|---|---|
| 캐시 | `st.cache_data` 또는 `data/cache/` 중 택일 | 로직을 Streamlit 없이 테스트하기 위해 `src/sources/http.py`의 **디스크 캐시**(TTL, 실패는 캐시 안 함)로 통일 |
| 모듈 배치 | `provenance.py`에 SeqRecord | 동일. 서열 검증은 `src/sequence.py`로 분리, UI는 `src/ui/` 로 분리 |
| ESMFold pLDDT 척도 | 언급 없음 | 실제 응답의 B-factor가 **0~1**(AlphaFold는 0~100)이라 `pdbutil.normalize_plddt`로 0~100 환산 |
| 구조 소스 | 소스 자동 선택 | AlphaFold DB는 **UniProt 전체 서열과 일치하는 항목만** 선택 가능(성숙 구간·변이체는 ESMFold). 소스가 서로 다른 구조를 비교하면 모델 차이 경고 표시 |
| 3D 뷰어 | `stmol` | `stmol` 대신 `py3Dmol` HTML을 `st.iframe`으로 임베드 (`st.components.v1.html`은 Streamlit에서 제거 예정). `stmol`은 의존성에서 쓰이지 않지만 requirements에 남아 있음 |
| 특허 | NCBI/EBI 특허 서열 소스 접근성 확인 | 자동 연동은 **구현하지 않음**(약관·접근성). 본문/서열목록 붙여넣기 + 외부 링크만 제공 (PRD F-6의 "불가 시 대체 경로") |
| 논문 | 초록 우선, 전문은 후순위 | 초록(제목+초록)만 자동 처리. 전문은 사용자가 붙여넣기 |
| 프리셋(논문/특허용) | 실제 논문 서열 1~2개 | 실제 서열을 원문에서 확인할 수 없어 **가상 샘플 텍스트**(서열도 가상)로 대체하고 UI에 명시 |
| 변이 문법 | `K12A`, `del`, `ins`, `trunc` | 동일. 위치는 항상 원본 기준(여러 변이를 한 번에 적용해도 밀리지 않음) |
| 발굴 방법/결합 대상 편집 | 검색 시 입력 | 사이드바에서 이후에도 편집 가능(설계된 서열은 편집 불가) |
| 미구현 | — | 펩타이드 DB(APD3/DRAMP), PDB 검색, 오픈액세스 전문 XML 파싱 (P2/후순위) |
## 변경 이력

### 2026-10-02 — 논문 검색을 "키워드 → 서열 바로 보기"로 변경
- **요청**: 논문 이름을 검색해 논문을 고르는 단계 없이 서열이 바로 보이게 하고, 논문 이름 검색은 선택 사항으로. 범위는 최근 몇 년이 아니라 지금까지의 모든 논문.
- **원인 확인**: Europe PMC 기본 정렬은 최근 논문에 치우쳐 상위 100편이 모두 2025~2026년이었다(전체 일치는 약 15,700편, 1975년 이전은 초록이 거의 없음).
- **변경**
  - `src/sources/europepmc.py`: 페이지네이션(`search_many`), 연도 구간별 균등 검색(`search_balanced`, 기본), 인용순·최신순, 오픈액세스 전문 텍스트(`fetch_fulltext`, 참고문헌 제외, 디스크 캐시 안 함)
  - `src/sources/literature.py`(신규): 여러 논문에서 서열을 모아 서열 단위로 묶고(논문 수·연도), 논문별 결합 대상 후보 연결
  - `src/sources/seqextract.py`: "서열인지 불확실한" 대문자 나열(MEDLINE, PRISMA, TEGDMA 등) 판별과 제목 대문자 단어 제외
  - `src/ui/tab_search.py`: ②의 기본 모드를 "서열 바로 찾기"로, 논문 이름 검색은 선택 모드, 표 행 클릭으로 채택
- **실제 데이터 확인**: `titanium binding peptide` 100편이 1977~2026년에 걸쳐 수집되고 RKLPDA, TBP-1(RKLPDAPGMHTW), TiBP1(RPRENRGRERGL), TBP54(FAETHRGFHFSF) 등이 추출됨. 전문 확인은 약 5초/논문.
- **알려진 한계**: 초록만으로는 서열이 빠진 논문이 많음(전문 확인으로 보완), 오탐 가능(불확실 표시로 완화), 전 기간은 구간별 상위 N편만 확인(전체 15,000여 편을 모두 읽지 않음).
### 2026-10-02 — "PET binding peptide" 검색이 엉뚱한 논문을 가져오는 문제
- **증상**: PET에 결합하는 펩타이드가 나와야 하는데 그렇지 않았다.
- **원인 확인**: Europe PMC에서 `PET binding peptide`는 57,603편이 걸리는데 상위는 대부분 PET **영상**(양전자방출단층촬영) 논문(CD105 펩타이드 PET 프로브 등)이었다. PET(폴리에틸렌 테레프탈레이트)라는 소재 뜻이 약어에 묻혔다. 결합 대상 제안 사전에도 PET 소재가 없었다.
- **변경**
  - `src/sources/query_assist.py`(신규): 재료 약어(PET, PS, PE, PP, PC, PVC, PLA, PMMA, PDMS, HA)를 정식 명칭으로 확장하고 겹치는 분야(영상, 포스파티딜세린, 폐색전증 등)를 제외. 사용자가 따옴표·괄호·AND/OR/NOT를 쓰면 건드리지 않음. 화면에 보정 내용과 실제 검색식을 표시하고 설정에서 끌 수 있음
  - `src/sources/binding.py`: PET(폴리에틸렌 테레프탈레이트)·PVC·PLA·나일론·폴리카보네이트·폴리프로필렌·폴리우레탄·마이크로플라스틱 추가 (단독 `PET`은 의학 영상과 겹쳐 소재 문맥이 있는 표현만 인식)
  - `src/sources/seqextract.py`: 전문에서 소프트웨어·시약·제조사 이름(CHARMM, RIDASCREEN®, NVIDIA 등)과 제목(REFERENCES 등)이 서열로 신뢰되던 문제를 줄임 — 비서열 단어 목록, ®·™, 제조사 문맥, 강/약 키워드 거리 구분
  - `src/ui/tab_search.py`: 초록만으로 서열이 10개 미만이면 전문 확인을 켜라고 안내
- **결과**: 확장 후 상위 논문이 PET 필름·PETase·플라스틱 결합 펩타이드 논문으로 바뀜(57,603편 → 2,069편). 전문 확인을 켜면 PET 관련 논문에서 DEYCCNN 등 서열이 추출됨.
- **한계**: PET에 결합하는 펩타이드 논문 자체가 많지 않아 초록만으로는 서열이 적다(전문 확인 권장). 효소 변이체 이름(LCCICCG 등)이 서열로 잡힐 수 있어 문맥 확인이 필요하다.
### 2026-10-02 — 본문(전문)까지 읽어서 서열 찾기 (WEWWHVFHHRLR, KGKEAAIAAAKA가 안 나온 문제)
- **요청**: 시간이 걸려도 되니 초록만 보지 말고 본문 원문을 확인해서 서열을 가져올 것.
- **원인 확인** (두 서열 모두 PMID 37735840 *In Silico Design and Analysis of Plastic-Binding Peptides* 한 편에 있음)
  1. 서열이 초록에 없고 본문(표·본문 문장)에만 있었다.
  2. 그 논문은 `isOpenAccess=N`(NIH 저자 원고)이라 전문 읽기 대상에서 빠졌고, Europe PMC 전문 API는 HTTP 500을 돌려줬다. 같은 PMCID가 NCBI PMC(efetch)에서는 본문이 내려왔다.
  3. 초록에 `poly(ethylene terephthalate)`로 적혀 있어 확장 검색어에 이 표기가 없었다.
  4. 연도 구간별 상위 N편만 가져와 순위 밖으로 밀렸다.
- **변경**
  - `europepmc.fetch_fulltext`: Europe PMC → 실패 시 NCBI PMC 순으로 시도, 본문이 3,000자 미만이면(초록뿐) 실패로 처리, 디스크 저장 안 함
  - `literature.find_sequences`: 오픈액세스 표시와 상관없이 **PMCID가 있는 논문의 본문을 읽음**, 3편 동시 병렬, 제목·초록 관련도 점수(peptide·binding·찾는 재료 용어)가 높은 논문부터 읽음, 결과 순서는 항상 동일, **본문을 읽지 못한 논문 목록**과 링크 제공
  - `europepmc.search_balanced`: 전체 일치 논문이 상한 이하이면 구간 분할 없이 **전부** 가져옴 (기본 상한 3,000편)
  - `query_assist`: PET 동의어(`poly(ethylene terephthalate)` 등) 추가, 검색어에서 핵심 용어 추출
  - `binding.suggest_targets`: 플라스틱 문맥이면 단독 `PET`도 소재로 인식, 서열 바로 옆 소재를 우선 정렬
  - UI: 본문 읽기가 **기본 켜짐**, 읽을 논문 수 기본 100편, 예상 소요시간 안내
- **실제 확인** (`PET binding peptide`, 전체 일치 2,329편 전부 + 본문 100편, 약 4분): `WEWWHVFHHRLR`, `KGKEAAIAAAKA` 모두 PMID 37735840 본문에서 추출, 결합 대상 후보 1순위 PET
- **한계**: 본문은 PMC에 공개된 논문만 읽을 수 있다(유료·비공개는 초록만, 읽지 못한 논문은 목록으로 표시). 본문 읽기 상한(기본 100편) 밖의 논문은 초록만 본다. 소프트웨어·약어·고분자 이름이 서열 후보로 잡히므로 알려진 것은 목록으로 거르고 나머지는 "문맥 불확실"로 숨긴다.
